## 2. What Are Embeddings?

An embedding is a numerical representation of an item, such as text, that is designed to capture useful characteristics of that item.

For example, consider these sentences:

- "How can I reset my password?"
- "I forgot my login credentials."
- "What is the weather today?"

The first two sentences have different words but similar meanings. A good text embedding model will often represent them as vectors that are closer together than the third sentence.

A simplified example:

```python
sentence_a = "How can I reset my password?"
sentence_b = "I forgot my login credentials."
sentence_c = "What is the weather today?"

# Illustrative only: real embeddings contain many numerical dimensions.
vector_a = [0.12, 0.84, -0.31, 0.55]
vector_b = [0.15, 0.79, -0.28, 0.51]
vector_c = [-0.62, 0.14, 0.91, -0.23]
```

These values are made up to demonstrate the concept. Real embeddings are generated by a trained model and usually have many more dimensions.

**Key idea:** Embeddings allow applications to compare representations numerically instead of relying only on matching words.

## 3. How Embeddings Fit into GenAI

A simplified text retrieval pipeline looks like this:

```text
Documents
    |
    v
Text Preprocessing
    |
    v
Embedding Model
    |
    v
Numerical Vectors
    |
    v
Similarity Search
    |
    v
Relevant Documents
    |
    v
LLM Application or RAG Pipeline
```

Embeddings are useful for:

- Semantic search
- Document retrieval
- Recommendation systems
- Duplicate detection
- Clustering similar text
- Finding related support tickets
- Retrieval-augmented generation

An embedding model is not the same thing as a generative LLM. An embedding model is optimized to produce useful vector representations, while a generative model produces content such as text or code.

Some model families can support both types of tasks, but the capabilities depend on the specific model.

## 4. Tokens, Embeddings, and Hidden States

These terms are related but different.

| Concept | Meaning |
|---|---|
| Tokenization | Splits text into tokens according to a tokenizer |
| Token | A unit processed by a language model; it may represent a word, part of a word, or another text unit |
| Token embedding | A numerical vector associated with a token |
| Hidden state | A model's contextual representation produced during its computation |
| Text embedding | A vector representing a larger text input, often a sentence, passage, or document |

For example:

```text
Text:
"The server is unavailable"

        |
        v

Tokenizer
        |
        v

Token IDs
        |
        v

Embedding Model
        |
        v

Text Vector
        |
        v

Similarity Comparison
```

The internal process differs between models. Many embedding models produce a final text vector by processing token representations and applying a model-specific pooling or projection strategy.

You generally do not need to implement that internal architecture yourself to use an embedding model effectively.

## 5. Keyword Search vs. Semantic Search

### Keyword Search

Keyword search looks for exact words or related terms using techniques such as matching, ranking, and text indexing.

Query:

```text
password recovery
```

A keyword-based system may prioritize documents containing those exact words.

### Semantic Search

Semantic search compares the meaning-related representations of a query and candidate documents.

Query:

```text
I cannot access my account because I forgot my password.
```

A semantic search system may retrieve a document titled:

```text
Steps to reset your login credentials
```

even if the document does not contain the exact words from the query.

| Feature | Keyword Search | Semantic Search |
|---|---|---|
| Main signal | Words and terms | Learned vector representations |
| Exact terminology | Often effective | Depends on the embedding model |
| Different wording | Can struggle without expansion | Can retrieve semantically similar content |
| Numeric identifiers | Often very effective | May not be reliable by itself |
| Synonyms and paraphrases | Depends on search method | Often handled more naturally |
| Common use | Product codes, exact names, filters | Questions, documents, related concepts |

Neither approach is universally better. Production systems often combine keyword search and semantic search to improve retrieval quality.

## 6. Understanding Vector Similarity

Once text is represented as vectors, you need a way to compare them.

Three common measures are cosine similarity, dot product, and Euclidean distance.

### 6.1 Cosine Similarity

Cosine similarity measures the angle between two vectors.

\[
\text{cosine similarity}(A,B)
=
\frac{A \cdot B}{\|A\|\|B\|}
\]

Where:

- \(A \cdot B\) is the dot product.
- \(\|A\|\) and \(\|B\|\) are the vector magnitudes.

For nonzero vectors, cosine similarity ranges from -1 to 1 mathematically. The practical distribution of scores depends on the embedding model and its training.

A higher score often indicates greater similarity for models designed for cosine-based retrieval. It does not represent a universal probability that two texts have the same meaning.

### 6.2 Dot Product

The dot product multiplies corresponding vector elements and sums the results.

\[
A \cdot B = \sum_{i=1}^{n} A_iB_i
\]

For normalized vectors, dot product and cosine similarity produce the same ranking.

For unnormalized vectors, vector magnitude can affect the score.

### 6.3 Euclidean Distance

Euclidean distance measures the straight-line distance between two vectors.

\[
d(A,B)=\sqrt{\sum_{i=1}^{n}(A_i-B_i)^2}
\]

For distance-based retrieval, smaller distances generally indicate closer vectors.

Use the similarity or distance function recommended for your embedding model and retrieval setup.

## 7. Calculate Similarity with Python

You can experiment with vectors before calling a real embedding API.

Install NumPy:

```bash
pip install numpy
```

Create `similarity.py`:

```python
import numpy as np


def cosine_similarity(
    vector_a: list[float],
    vector_b: list[float],
) -> float:
    a = np.asarray(vector_a, dtype=float)
    b = np.asarray(vector_b, dtype=float)

    if a.ndim != 1 or b.ndim != 1:
        raise ValueError("Vectors must be one-dimensional.")

    if a.shape != b.shape:
        raise ValueError("Vectors must have the same dimensions.")

    norm_a = np.linalg.norm(a)
    norm_b = np.linalg.norm(b)

    if norm_a == 0 or norm_b == 0:
        raise ValueError("Cosine similarity is undefined for zero vectors.")

    return float(np.dot(a, b) / (norm_a * norm_b))


vector_a = [0.8, 0.2, 0.5]
vector_b = [0.7, 0.3, 0.4]
vector_c = [-0.5, 0.8, -0.1]

print(cosine_similarity(vector_a, vector_b))
print(cosine_similarity(vector_a, vector_c))
```

These are illustrative vectors, not embeddings generated from actual text.

The first pair points in a more similar direction than the second pair. This example demonstrates the mathematics, but meaningful text retrieval requires vectors generated by a suitable embedding model.

## 8. Generate Real Text Embeddings

Now use a real embedding model.

The following example uses the OpenAI Python SDK. Other providers offer similar embedding APIs.

Install the SDK:

```bash
pip install openai python-dotenv numpy
```

Configure your `.env` file:

```text
OPENAI_API_KEY=your_api_key_here
```

Do not commit this file to GitHub.

Create `embedding_search.py`:

```python
import os

import numpy as np
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()

if not os.getenv("OPENAI_API_KEY"):
    raise RuntimeError("OPENAI_API_KEY is not configured.")

client = OpenAI()


def embed_texts(texts: list[str]) -> list[list[float]]:
    if not texts:
        return []

    response = client.embeddings.create(
        model="text-embedding-3-small",
        input=texts,
    )

    # Preserve the original input order.
    ordered_data = sorted(
        response.data,
        key=lambda item: item.index,
    )

    return [item.embedding for item in ordered_data]


documents = [
    "Reset your password from the account settings page.",
    "Update your billing details in the subscription portal.",
    "Troubleshoot a server that is not responding.",
    "Recover access when you forget your login credentials.",
]

document_vectors = embed_texts(documents)

print("Documents:", len(documents))
print("Vector dimensions:", len(document_vectors[0]))
```

The model name is an example. Check your provider's current documentation for model availability, dimensions, pricing, and supported input limits.

Each document is converted into a numerical vector. The vectors can now be compared with a query vector.

## 9. Build a Simple Semantic Search Engine

Add the following code to the same file:

```python
def semantic_search(
    query: str,
    documents: list[str],
    document_vectors: list[list[float]],
    top_k: int = 3,
) -> list[tuple[str, float]]:
    if len(documents) != len(document_vectors):
        raise ValueError(
            "Each document must have a corresponding vector."
        )

    if not documents:
        return []

    if not query.strip():
        raise ValueError("Query cannot be empty.")

    if top_k < 1:
        raise ValueError("top_k must be at least 1.")

    query_vector = embed_texts([query])[0]

    matrix = np.asarray(document_vectors, dtype=float)
    query_array = np.asarray(query_vector, dtype=float)

    if matrix.ndim != 2 or query_array.ndim != 1:
        raise ValueError("Unexpected embedding dimensions.")

    if matrix.shape[1] != query_array.shape[0]:
        raise ValueError("Query and document dimensions do not match.")

    matrix_norms = np.linalg.norm(matrix, axis=1)
    query_norm = np.linalg.norm(query_array)

    if query_norm == 0 or np.any(matrix_norms == 0):
        raise ValueError("Cannot compare zero vectors.")

    scores = (
        matrix @ query_array
    ) / (matrix_norms * query_norm)

    ranked_indices = np.argsort(scores)[::-1][:top_k]

    return [
        (documents[index], float(scores[index]))
        for index in ranked_indices
    ]


query = "I cannot log in because I forgot my password"

results = semantic_search(
    query=query,
    documents=documents,
    document_vectors=document_vectors,
    top_k=3,
)

for rank, (document, score) in enumerate(results, start=1):
    print(f"{rank}. Score: {score:.4f}")
    print(f"   Document: {document}")
```

### What This Code Does

1. Generates an embedding for the query.
2. Compares the query vector with stored document vectors.
3. Calculates cosine similarity.
4. Sorts documents by similarity.
5. Returns the top results.

For this small example, the vectors are held in memory. The document embeddings can be generated once and reused until the underlying documents or embedding model changes.

For large datasets, a vector database or a specialized vector index can perform retrieval more efficiently. You will explore these systems in Module 07.

## 10. Important Embedding Design Decisions

### 10.1 Embedding Dimensions

An embedding may contain hundreds or thousands of numerical values.

The dimension count depends on the selected model and configuration.

Higher dimensionality does not automatically guarantee better retrieval quality. Evaluate models on your actual task.

### 10.2 Normalize or Not?

Some systems normalize vectors so their magnitude becomes 1.

Normalization makes cosine similarity equivalent to dot product for the normalized vectors.

Do not assume that every model returns normalized vectors. Follow the model's recommendations and use a consistent similarity calculation.

### 10.3 Query and Document Compatibility

For a meaningful comparison, query and document vectors must be compatible.

In particular:

- Use the same embedding model for both sides unless the model explicitly supports a compatible query/document setup.
- Keep vector dimensions consistent.
- Follow any model-specific query and document formatting instructions.
- Re-embed documents when switching to an incompatible embedding model.

### 10.4 Chunking and Long Documents

Long documents may exceed a model's input limits or contain multiple topics.

A common retrieval workflow is:

```text
Long Document
      |
      v
Split into Chunks
      |
      v
Generate an Embedding for Each Chunk
      |
      v
Store Text + Metadata + Vector
      |
      v
Embed the User Query
      |
      v
Retrieve Relevant Chunks
```

Chunking strategies and vector storage will be covered in the next modules. For now, understand that a single vector for an entire long document may not be sufficient for precise retrieval.

## 11. Evaluate Semantic Search Quality

A search system is useful only if it retrieves relevant results.

Create a small evaluation dataset with queries and expected relevant documents.

Example:

| Query | Expected Relevant Document |
|---|---|
| I forgot my password | Reset your password from the account settings page |
| My subscription payment information is wrong | Update your billing details in the subscription portal |
| The server is not responding | Troubleshoot a server that is not responding |

Evaluate your search system using:

- **Precision@k:** What proportion of the top-k results are relevant?
- **Recall@k:** What proportion of all known relevant documents appear in the top-k results?
- **MRR:** How highly does the system rank the first relevant result?
- **Latency:** How long does retrieval take?
- **Cost:** How much does embedding generation and query processing cost?

For a query with known relevant results:

\[
\text{Precision@k}
=
\frac{\text{Relevant results in top-k}}{k}
\]

If fewer than \(k\) results exist, define clearly whether your evaluation uses the requested \(k\) or the number of returned results.

Do not rely on similarity scores alone. A high score does not guarantee relevance, and thresholds must be calibrated against your dataset.

## 12. Common Mistakes

Avoid these mistakes when implementing embeddings:

- Treating embeddings as human-readable meanings.
- Assuming similar words always produce similar vectors.
- Assuming a high similarity score guarantees relevance.
- Comparing vectors from incompatible embedding models.
- Recalculating every document embedding for every query.
- Ignoring model input limits and API rate limits.
- Using semantic search for exact identifiers without testing it.
- Forgetting to keep document text and metadata associated with each vector.
- Changing embedding models without re-embedding stored documents.
- Evaluating only a few hand-picked examples.
- Sending sensitive data to external providers without considering privacy and data-handling requirements.

## 14. Interview Questions

**Q1. What is an embedding?**

An embedding is a numerical vector representing an item in a learned vector space. Text embeddings are commonly used to compare semantic similarity.

**Q2. What is the difference between token embeddings and text embeddings?**

Token embeddings represent individual tokens within a model's processing pipeline. Text embeddings generally represent a larger text unit such as a sentence or document.

**Q3. How does semantic search work?**

It embeds a query and candidate documents into compatible vector spaces, calculates similarity or distance, and ranks documents accordingly.

**Q4. What is cosine similarity?**

Cosine similarity measures the angle-based similarity between two nonzero vectors.

**Q5. What is the difference between cosine similarity and Euclidean distance?**

Cosine similarity compares vector direction, while Euclidean distance measures straight-line distance. Their rankings can differ depending on vector magnitudes and normalization.

**Q6. Why should query and document embeddings use compatible models?**

Incompatible models may produce vectors whose dimensions or learned spaces do not align, making similarity scores meaningless.

**Q7. Are embeddings always better than keyword search?**

No. Keyword search is often better for exact identifiers and literal matches. Semantic search helps with meaning and paraphrases. Hybrid retrieval can combine their strengths.

**Q8. What are Precision@k and Recall@k?**

Precision@k measures the proportion of retrieved top-k results that are relevant. Recall@k measures how many of the known relevant results appear in the top-k results.

**Q9. Why are embeddings important for RAG?**

They help retrieve semantically relevant document chunks that can be supplied as context to a generative model.

**Q10. When should document embeddings be regenerated?**

When the underlying text changes or when a model or configuration change makes the existing vectors incompatible with the new retrieval setup.
