## 🧠 2. What Is a Vector Database?

A **vector database** stores and searches numerical vectors, often alongside the text and metadata associated with those vectors.

In the previous module, you learned how to generate embeddings and compare them with cosine similarity.

Now imagine storing embeddings for 100,000 documents.

Calculating the similarity between a query and every document can become expensive as the dataset grows. A vector database provides specialized storage and search capabilities to make retrieval more practical.

### Example: Document Storage

Suppose your application contains three documents:

| ID | Document | Category |
|---|---|---|
| `doc_001` | How to reset an account password | Support |
| `doc_002` | How to update subscription billing | Billing |
| `doc_003` | How to troubleshoot a server | Engineering |

A retrieval record may contain:

- **ID:** A unique identifier.
- **Vector:** The document's embedding.
- **Text:** The original document or chunk.
- **Metadata:** Category, source, date, permissions, or other attributes.

Conceptually:

```text
Record
├── ID: doc_001
├── Vector: [0.12, -0.43, 0.81, ...]
├── Text: "How to reset an account password"
└── Metadata
    ├── category: "support"
    └── source: "help-center"
```

The vector values above are illustrative. Real vectors contain the dimensions produced by your embedding model.

## 🆚 3. Traditional Database vs. Vector Database

| Feature | Traditional Database | Vector Database |
|---|---|---|
| Primary purpose | Store and query structured data | Store and search vector representations |
| Common query | Find a user by ID | Find documents similar to a query vector |
| Exact matching | Excellent | Not its main purpose |
| Semantic retrieval | Requires additional methods | Core capability |
| Filtering | SQL or database-specific filters | Often supports metadata filters |
| Common examples | PostgreSQL, MySQL, SQL Server | Qdrant, ChromaDB, Milvus |
| Typical AI use | Users, orders, transactions | Embeddings and similarity retrieval |

**Important:** These categories overlap. PostgreSQL with pgvector, for example, can support relational data and vector search in the same database.

A vector database is not automatically the best solution for every project. Select your storage system based on data size, filtering needs, infrastructure, security, latency, and operational complexity.

## 🧩 4. Core Concepts You Must Understand

### 4.1 Vector

A vector is a sequence of numerical values representing an item.

```python
embedding = [0.12, -0.43, 0.81, 0.27]
```

Vectors generated by the same compatible embedding model can be compared using an appropriate similarity or distance metric.

### 4.2 Collection

A collection is a logical group of records in a vector database.

For example:

```text
company_documents
├── HR policies
├── Technical documentation
├── Product documentation
└── Support articles
```

The exact terminology varies by database. Some systems use terms such as *collection*, *table*, or *index* for related concepts.

### 4.3 Metadata or Payload

Metadata stores additional information about a document.

```python
metadata = {
    "category": "hr",
    "department": "human_resources",
    "source": "employee_handbook.pdf",
    "page": 12,
}
```

Metadata lets you filter results without relying only on semantic similarity.

### 4.4 Similarity Metric

A similarity metric determines how candidate vectors are compared.

| Metric | General Interpretation |
|---|---|
| Cosine similarity | Compares vector direction |
| Dot product | Compares aligned vector values and may depend on magnitude |
| Euclidean distance | Measures straight-line distance |

The best metric depends on your embedding model and how its vectors are intended to be used.

### 4.5 Top-K Retrieval

Top-k retrieval returns the best-ranked `k` candidates.

For example:

```python
top_k = 5
```

A query with `top_k=5` asks for up to five results, depending on the database and available matches.

### 4.6 Vector Index

A vector index helps the database find nearest neighbors efficiently.

A common family of methods is **Approximate Nearest Neighbor (ANN)** search. ANN methods trade some degree of search exactness for better performance at scale.

Approximate retrieval is not guaranteed to return the exact mathematical nearest neighbors. You should evaluate the trade-off for your application.

## ⚙️ 5. How Vector Retrieval Works

A typical retrieval workflow looks like this:

```text
                 DOCUMENT INGESTION

Documents → Split into Chunks → Generate Embeddings
                                      │
                                      ▼
                            Store Vectors + Metadata
                                      │
                                      ▼
                              Vector Database


                   QUERY-TIME RETRIEVAL

User Query → Generate Query Embedding
                         │
                         ▼
               Similarity Search + Filters
                         │
                         ▼
                  Ranked Results
                         │
                         ▼
             Application / Future RAG System
```

Document embeddings are generally created during ingestion and reused for later queries. A query embedding is generated when a user searches.

The document and query embeddings must be compatible. If you change to an incompatible embedding model, you will generally need to regenerate the stored document vectors.

## Step 3 — Create a Persistent Vector Collection

Create `src/vector_store.py`:

```python
import chromadb


client = chromadb.PersistentClient(
    path="./chroma_data"
)

collection = client.get_or_create_collection(
    name="knowledge_base",
    metadata={"description": "Learning vector retrieval"},
)


documents = [
    "Reset your password from account settings.",
    "Update payment information in your billing portal.",
    "Troubleshoot a server that is not responding.",
    "Recover access to an account when credentials are forgotten.",
]

ids = [
    "doc_001",
    "doc_002",
    "doc_003",
    "doc_004",
]

metadatas = [
    {"category": "support"},
    {"category": "billing"},
    {"category": "engineering"},
    {"category": "support"},
]


collection.upsert(
    ids=ids,
    documents=documents,
    metadatas=metadatas,
)

print("Documents stored successfully.")
print("Collection count:", collection.count())
```

### What Is Happening?

- `PersistentClient` creates a local persistent ChromaDB client.
- `get_or_create_collection` opens or creates the collection.
- `upsert` inserts records or updates existing records with the same IDs.
- `documents` stores the text.
- `metadatas` stores filtering information.

In this example, ChromaDB uses its configured default embedding function. That makes the demonstration convenient, but it is important to be explicit about the embedding model in production.

**Production rule:** Choose and configure an embedding model deliberately. Use compatible query and document embeddings, and avoid silently changing models between ingestion and search.

## Step 4 — Retrieve Relevant Documents

Create `src/retrieval.py`:

```python
from src.vector_store import collection


def search_documents(
    query: str,
    top_k: int = 3,
    category: str | None = None,
) -> list[dict]:
    if not query.strip():
        raise ValueError("Query cannot be empty.")

    if top_k < 1:
        raise ValueError("top_k must be at least 1.")

    where = {"category": category} if category else None

    results = collection.query(
        query_texts=[query],
        n_results=top_k,
        where=where,
    )

    documents = results["documents"][0] or []
    ids = results["ids"][0] or []
    metadatas = results["metadatas"][0] or []
    distances = results["distances"][0] or []

    return [
        {
            "id": document_id,
            "document": document,
            "metadata": metadata,
            "distance": distance,
        }
        for document_id, document, metadata, distance in zip(
            ids,
            documents,
            metadatas,
            distances,
        )
    ]


if __name__ == "__main__":
    results = search_documents(
        query="I forgot my login password",
        top_k=3,
    )

    for result in results:
        print(result)
```

### Understanding the Result

The example returns a distance, not a universal similarity score.

For a cosine-distance configuration, smaller distances generally indicate closer vectors. The exact interpretation depends on the configured metric and database.

Do not treat a distance as a probability. Calibrate any relevance threshold using a labeled evaluation dataset.

## Step 5 — Apply Metadata Filters

Search only documents in the support category:

```python
results = search_documents(
    query="I cannot access my account",
    top_k=3,
    category="support",
)
```

Metadata filtering is useful when an application needs to restrict retrieval by department, document type, tenant, date, or another attribute.

**Security note:** Metadata filters alone are not an authorization system. Enforce access permissions in trusted backend code and ensure users cannot manipulate filters to access unauthorized records.

## 🔍 7. Understand Retrieval Quality

A vector database can return the nearest vectors without guaranteeing that they answer the user's question.

Evaluate retrieval quality separately from storage performance.

### Key Metrics

| Metric | What It Measures |
|---|---|
| Precision@K | Proportion of the top-k results that are relevant |
| Recall@K | Proportion of known relevant items retrieved in the top-k |
| MRR | Ranking position of the first relevant result |
| Latency | Time required to complete retrieval |
| Indexing time | Time required to prepare and store records |
| Storage cost | Space required for vectors, metadata, and indexes |

### Example

Suppose the top five retrieved documents contain three relevant documents.

\[
\text{Precision@5} = \frac{3}{5} = 0.60
\]

The precision is 60%.

Recall requires knowing the total number of relevant documents for that query. For example, if four documents are relevant in the complete dataset and three appear in the top five:

\[
\text{Recall@5} = \frac{3}{4} = 0.75
\]

The recall is 75%.

These metrics help you decide whether to change the embedding model, chunking strategy, filters, index configuration, or retrieval settings.

## 🆚 8. Choosing a Vector Storage Technology

### ChromaDB

**Best for:** Learning, prototypes, local projects, and straightforward vector search.

- Simple Python workflow.
- Convenient local persistence.
- Supports metadata and vector retrieval.
- Useful for learning the foundations.

### Qdrant

**Best for:** Applications needing a dedicated vector search service and more explicit retrieval infrastructure.

- Supports vector search and payload filtering.
- Offers local and service-based deployment options.
- Useful for more advanced retrieval systems.

### PostgreSQL + pgvector

**Best for:** Applications that already use PostgreSQL and want relational data and vector search together.

- Combines SQL queries and vector operations.
- Supports relational joins and metadata filtering.
- Can simplify architecture when PostgreSQL is already the main database.

### Quick Comparison

| Requirement | Suggested Starting Point |
|---|---|
| Learn vector retrieval quickly | ChromaDB |
| Build a dedicated vector retrieval service | Qdrant |
| Combine business data and vectors in PostgreSQL | pgvector |
| Exact ID or transactional queries | Traditional database indexes |
| Large-scale retrieval | Benchmark suitable systems against your workload |

There is no universal winner. Test your expected data volume, filters, concurrency, security model, and latency requirements before choosing a production database.

## ⚠️ 10. Common Mistakes and Best Practices

### Common Mistakes

- Storing vectors without keeping track of their source text.
- Using incompatible embedding models for queries and documents.
- Re-embedding unchanged documents for every query.
- Assuming the nearest vector must be relevant.
- Treating similarity scores or distances as probabilities.
- Ignoring metadata and access permissions.
- Returning an arbitrary number of results without testing retrieval quality.
- Switching embedding models without rebuilding incompatible vectors.
- Choosing a database based on popularity rather than requirements.

### Best Practices

- Use stable document IDs.
- Store source identifiers and useful metadata.
- Keep the embedding model and configuration explicit.
- Batch ingestion where appropriate.
- Measure retrieval quality and latency.
- Apply authorization checks in trusted application code.
- Use realistic evaluation queries.
- Monitor API failures, storage usage, and retrieval performance.
- Re-index or re-embed documents when necessary.
- Keep vector storage separate from business authorization decisions.

## 🎤 11. Interview Questions

**Q1. What is a vector database?**

A system designed to store vectors and retrieve similar vectors, often with associated text and metadata.

**Q2. Why use a vector database instead of comparing every vector manually?**

A vector database provides storage, indexing, filtering, and retrieval capabilities that can make similarity search more efficient at scale.

**Q3. What is approximate nearest-neighbor search?**

ANN search retrieves vectors that are likely to be close to a query vector while often reducing search time compared with exhaustive search.

**Q4. What is the difference between a vector and metadata?**

A vector represents an item numerically for similarity comparisons. Metadata provides descriptive fields that support filtering, organization, and application logic.

**Q5. What is top-k retrieval?**

It returns up to the k highest-ranked candidates according to the selected retrieval method.

**Q6. What is the difference between similarity and distance?**

Similarity generally increases as items become more alike. Distance generally decreases as vectors become closer. The exact meaning depends on the metric.

**Q7. What is metadata filtering?**

It restricts search candidates based on conditions such as category, source, department, or date.

**Q8. Can PostgreSQL be used as a vector database?**

Yes. PostgreSQL with pgvector supports vector storage and similarity search alongside relational data.

**Q9. How do you evaluate retrieval quality?**

Use labeled queries and relevance judgments to calculate metrics such as Precision@K, Recall@K, and MRR, while measuring latency separately.

**Q10. Why are vector databases important for RAG?**

They help retrieve relevant document chunks that can be provided to an LLM as contextual information.
